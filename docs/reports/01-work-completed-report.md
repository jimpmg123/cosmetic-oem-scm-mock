# Applicell 화장품 사업 — 생산·물류 추적 웹 개발 진행 보고

**작성일:** 2026-06-19  
**독자:** Applicell 경영진  
**프로젝트:** 위탁생산 물량·수율(투입 대비 회수율)·대사 추적 웹 시스템 (화장품 사업용)  
**현재 단계:** 화면·업무 흐름 **시연 가능한 목업 완료** → 실제 운영 시스템으로 가기 전 **구조 확인 단계**

---

## 경영진 요약 (1페이지)

### 무엇을 만들고 있는가

Applicell이 위탁 공장에 원자재를 보내고, 공장이 생산한 완제품이 창고에 입고될 때까지 **「누가 몇 개를 보냈고, 몇 개를 만들었고, 몇 개가 들어왔는지」** 를 한곳에서 맞춰 보는 **웹 관리 시스템**이다.

엑셀·메신저·ERP 화면을 오가며 숫자를 대조하던 방식을, **브랜드(Applicell) · 위탁 공장 · 창고**가 같은 화면을 보도록 줄이는 것이 목표이다.

### 지금까지 무엇이 끝났는가

| 구분 | 상태 |
|------|------|
| 업무 흐름 설계 | ✅ 물량 → 기간 지시 → 일별 생산 → 출하 → 입고 → 대사·수율 |
| Applicell(브랜드)용 화면 | ✅ 대시보드, 물량 관리, 지시, 대사, 수율 조회 등 |
| 위탁 공장용 화면 | ✅ 일별 생산 일지, 원자재 입고 확인, 완제품 출하 등 |
| 창고용 모바일 화면 | ✅ 입고 목록, 수량 확인 (스마트폰 형태) |
| 다국어 | ✅ 한국어 / 중국어 / 영어 |
| 기획·화면 문서 | ✅ 20여 건 정리 |

**브라우저에서 데모 시연이 가능한 수준**까지 왔다. 경영진·현장 담당자에게 「이런 시스템이 됩니다」를 보여 줄 수 있다.

### 아직 하지 않은 것 (중요)

| 구분 | 상태 | 경영 관점 의미 |
|------|------|----------------|
| 실제 데이터 저장 (DB) | ❌ | 새로고침하면 초기화 — **운영 불가** |
| 로그인·계정·권한 | ❌ | 역할 전환은 데모용 버튼만 |
| ERP(NetSuite 등) 연동 | ❌ | 제품·재고 마스터는 아직 수동 가정 |
| Applicell 실제 조직 구조 반영 | ❌ | **몇 개 공장, 누가 A/B/C인지** 확인 필요 |

### 경영진이 지금 결정·확인해 주셔야 할 것

1. **Applicell의 실제 거래 구조** — 브랜드·공장·창고 관계가 지금 화면 구조와 같은지 (→ 별첨 질문 리스트)
2. **몇 개 공장에 적용할 것인지** — 1곳 파일럿 vs 전 공장 표준화
3. **1차 목표 범위** — 「화면만 더 다듬기」 vs 「실제 데이터로 쓸 수 있게 만들기」

## 1. 사업 배경과 해결하려는 문제

### 1.1 현장에서 자주 생기는 문제

- Applicell이 보낸 원자재 분량과, 공장이 받았다고 하는 분량이 **다르다**
- 공장 생산 수와 창고 입고 수가 **다르다**
- 중국 생산 관련 작업은 항상 최악을 가정하고 보안과 제품 정품 인증을 확인 가능하게 해야한다.
- 「이번 달 몇 개 만들라」는 지시와 실제 입고가 **맞는지 한눈에 안 보인다**
- 수율을 **누가 기준으로** 계산하는지 (공장 주장 vs 창고 확인) 혼선이 있다

### 1.2 이 시스템이 주는 가치 (목표)

| 이해관계자 | 기대 효과 |
|------------|-----------|
| **Applicell 경영·기획** | 기간별 목표 대비 입고 달성, 물량 단위 수율·손실 파악 |
| **Applicell 운영** | 여러 공장·여러 제품 라인을 한 화면에서 추적 |
| **위탁 공장** | 지시·코멘트·일지 입력이 명확해 협의 비용 감소 |
| **창고** | 모바일로 입고 확인, 출하 수량과 즉시 대조 |

---

## 2. 시스템이 다루는 업무 (쉬운 설명)

### 2.1 세 역할

| 역할 | 실무에서 누구 | 하는 일 |
|------|---------------|---------|
| **A (브랜드)** | Applicell | 원자재 출하, 「~일까지 y개」 지시, 최종 대사·수율 확인 |
| **B (위탁 공장)** | OEM 공장 | 매일 생산 일지, 원자재 실수령 확인, 완제품 창고로 발송 |
| **C (창고)** | 물류·FBA·자체 창고 | 실제 입고 수량 확인 |

> 현재 목업은 **Applicell = A(브랜드)** 를 기본으로 설계되어 있다. 실제 Applicell 조직이 이와 다르면 구조 수정이 필요하다.

### 2.2 핵심 관리 단위

| 용어 | 쉬운 설명 |
|------|-----------|
| **물량** | Applicell이 공장에 보낸 「이 자재로 이 제품을 이만큼 만들 수 있다」는 생산 단위 |
| **기간 지시** | 「6월 30일까지 500개」처럼 기한·수량·메모가 있는 생산·출하 목표 |
| **일별 생산 일지** | 공장이 매일 적는 생산 수, 불량, QC 등 |
| **대사** | 공장이 보냈다 vs 창고가 받았다 — 숫자 맞추기 |
| **수율** | Applicell이 보낸 분량 대비 **창고가 확인한 입고** (공장이 말한 생산 수가 아님) |

## 3. 완료된 화면 (역할별)

### 3.1 Applicell (브랜드) — PC 웹

| 화면 | 무엇을 하나 |
|------|-------------|
| 대시보드 | 진행 중인 물량·지시·입고 이슈 한눈에 | 
| 작업 현황 | 제품 라인·물량별 달성률 |
| 물량 | 등록·목록·상세 (목표, 기한, 누적 입고) |
| 원자재 출하 | Applicell → 공장 출하 기록 |
| 이송 대조 | Applicell 출하 vs 공장 수령 확인 |
| 기간 지시 | 「~일까지 y개」 발행·진행률 |
| 지시 실적 분석 | 기간별 생산·출하·입고 그래프 |
| 대사·수율 | 지시 달성 / 공장↔창고 차이 / 물량 수율 |
| 제품 카탈로그 | 브랜드 라인·제품·위탁 공장 목록 |

### 3.2 위탁 공장 — PC 웹

| 화면 | 무엇을 하나 |
|------|-------------|
| 공장 대시보드 | 담당 물량, 다가오는 지시, 오늘 일지 미작성 알림 |
| 일별 생산 일지 | 생산·불량 입력 (QC·원재료·첨부 선택) |
| 일지 이력 | 과거 제출 내역 검토 |
| 생산 캘린더 | 날짜별 생산 추이·히트맵 |
| 원재료 입고 확인 | Applicell 출하 vs 공장 실수령 (이송 손실) |
| 완제품 출하 | 창고로 보낸 수량 등록 |

### 3.3 창고 — 모바일 웹

| 화면 | 무엇을 하나 |
|------|-------------|
| 입고 목록 | 도착 예정 건 |
| 입고 확인 | 실제 받은 수량 입력 |
| 차이 처리 | 출하 수량과 입고 수량 불일치 |

### 3.4 공통

- 역할별로 **보이는 메뉴가 다름** (데모 시 역할 전환 가능, 아직 역할 분리가 명확하게 되지는 않았음)
- **한국어·중국어·영어** 전환
- 수율·E2E(목표 달성률) 등 용어에 **설명 툴팁** 제공

## 4. 한 번에 보는 업무 흐름 (시연 시나리오)

```
① Applicell — 물량 등록 + 공장으로 원자재 출하 기록
② Applicell — 「6/30까지 500개」 기간 지시 (명절·블프 등 메모 포함)
③ 공장 — 원자재 실수령 확인 (출하 vs 수령 차이)
④ 공장 — 매일 생산 일지 작성
⑤ 공장 — 완제품 창고로 출하 등록
⑥ 창고 — 모바일에서 입고 수량 확인
⑦ Applicell — 대사 화면에서 차이·지시 달성·수율 확인
```

데모 접속: **http://localhost:3000** (시연 시 안내)

## 5. 개발 진행도

### 5.1 단계별 위치

```
[완료] 업무·화면 기획

[진행 전] 실제 DB·로그인·서버 구축
[진행 전] ERP 연동 · 파일럿 운영
```

## 6. 한계와 리스크 (경영진이 알아두실 점)

### 6.1 지금은 「시연용」이다

- 입력한 데이터가 **저장되지 않는다** (브라우저 데모)
- 실제 직원 계정·보안 **없음**
- 엑셀·ERP와 **자동 연동 없음**

→ **실무 투입 전** 반드시 「실운영 버전」 개발 단계가 필요하다.

### 6.2 Applicell 구조를 모르면 잘못된 방향으로 갈 수 있다

현재 목업은 아래를 **가정**한다.

- Applicell이 **브랜드(발주·지시)** 역할
- 위탁 **공장 1곳** 중심 데모 (여러 곳은 목록으로 확장 가능해 보이지만 설계 미확정)
- Applicell이 공장보다 **상위 권한** (지시·대사 최종)

실제로 아래가 다르면 **시스템 골격을 바꿔야** 한다.

- 원자재를 보내는 주체가 **여러 곳**
- 공장과 **동등한 계약** 관계 (중국 내 거래 등)
- 창고가 **Amazon FBA·3PL** 등 외부
- **여러 공장**에 동시 적용·데이터 통합/분리 정책

→ **`02-customer-discovery-questions.md`** 에 경영진 확인용 질문을 정리해 두었다.

### 6.3 남은 기술 과제 (요약)

| 항목 | 설명 |
|------|------|
| 창고 입고 ↔ 물량 출하 연결 | 일부 화면이 아직 예전 데모 구조와 혼재 |
| 사용자·회사·감사 로그 | 화면만 있고 실기능 없음 |
| ERP 메뉴 | 데모용 placeholder — 운영 메뉴와 중복 |

## 7. 결론 및 제안

### 완료된 것

Applicell 화장품 위탁생산의 **핵심 업무 흐름을 웹 화면으로 구현**했고, 경영진·현장 담당자에게 **「이런 시스템」** 을 보여 줄 수 있는 단계에 도달했다.

### 다음에 필요한 것

| 순서 | 내용 | 담당 |
|------|------|------|
| 1 | **경영진 인터뷰** — 조직·공장·창고 구조, 다공장 적용 범위 | Applicell + 개발 |
| 2 | **1차 범위 확정** — 파일럿 공장, MVP(실데이터) vs 풀 연동 | 경영진 의사결정 |
| 3 | **실운영 개발 착수** — DB, 로그인, 서버, (선택) ERP 연동 | 개발 |

### 경영진께 드리는 제안

1. **파일럿 1개 공장** 지정 — 실제 데이터로 end-to-end 1사이클 검증  
2. **수율·KPI 정의** — Applicell이 쓰는 공식과 목업 정의 일치 여부 확인

## 용어 정리

| 용어 | 의미 |
|------|------|
| **A (브랜드)** | Applicell처럼 발주·원자재 출하·생산 지시·최종 확인을 하는 주체 |
| **B (위탁 공장)** | 원자재를 받아 생산하고, 완제품을 창고로 보내는 OEM 공장 |
| **C (창고)** | 완제품을 실제로 받아 수량을 확인하는 창고·FBA·3PL |
| **물량** | A가 B에 보낸 원자재로 만들 수 있는 생산 가능 분량의 단위 |
| **grant** | A가 B에 보낸 발송 기준 수량. 수율 계산의 분모 |
| **기간 지시** | 「언제까지 몇 개」처럼 기간과 목표 수량이 있는 생산·출하 지시 |
| **대사** | A 출하, B 생산·출하, C 입고 숫자가 맞는지 비교하는 작업 |
| **수율** | 투입 대비 회수율. A가 보낸 grant 대비 C가 실제 확인한 입고량 |
| **E2E** | 목표 달성률. A가 정한 목표 수량 대비 C가 실제 확인한 입고량 |
| **달성도** | 진행 중 목표에 얼마나 가까워졌는지 보는 지표 |
| **로스 여유** | 생산·이송 중 손실을 감안해 목표보다 더 잡는 여유분 |
| **ERP / NetSuite** | 기존 제품·재고·발주 등 회사 운영 데이터를 관리하는 외부/기존 시스템 |
| **MVP** | 실제 데이터로 최소 업무 흐름을 운영해 볼 수 있는 1차 실사용 버전 |
