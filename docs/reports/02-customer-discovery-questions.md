## 이 문서를 왜 드리는가

지금까지 만든 것은 **「브랜드 1곳 → 위탁 공장 1곳 → 창고 1곳」** 을 가정한 **시연용 화면**이다.

Applicell 실제 사업 구조가 이와 다르면, **지금 만든 화면을 그대로 쓸 수 없고** 권한·메뉴·데이터 구조를 **처음부터 다시 잡아야** 한다.

예를 들어:

- 원자재를 보내는 쪽이 Applicell **한 곳이 아닐** 수 있다
- Applicell과 공장이 **상하 관계가 아닌** 동등 계약일 수 있다 (예: 중국 내 거래)
- **여러 공장**에 같은 시스템을 쓸지, **한 공장만** 파일럿할지
- 창고가 Applicell 자체인지, **Amazon FBA·물류 대행**인지

**구조를 먼저 확인한 뒤** 실제 운영 개발(DB·로그인·연동)에 들어가야 **비용과 일정을 낭비하지 않습니다.**

## 모든 답을 한 번에 주실 필요는 없습니다 — 개발 2단계 분리

확인 과정에서 한 가지가 분명해졌습니다: **A→B(브랜드→공장) 구간은 마케팅 방향과 무관하게 지금 개발할 수 있고, B→C(공장→창고·판매) 구간은 판매 채널·물류 방식이 정해져야 설계할 수 있습니다.**

| 구간 | 무엇 | 막는 결정 | 지금 가능? |
|------|------|-----------|------------|
| **A→B** | 자재 묶음 · 기간 지시 · 생산 일지 · 원자재 입고 — **브랜드와 공장 사이의 일** | **조직·거래 구조** (아래 1번 섹션) — *마케팅과 무관* | ✅ 조직 구조만 확정되면 바로 |
| **B→C** | 창고 입고 · B↔C 대사 · 최종 수율 — **"C가 누구냐"에 달림** | **판매 채널·물류 방식** (5번 섹션 + `03` 보고서) | ⚠️ 마케팅·채널 결정 후 |

> 공장은 제품을 **티몰에 팔든 위챗에 팔든 똑같이 생산**합니다. 그래서 A→B는 채널과 무관합니다.
> 반면 창고(C)가 **자체 창고냐 / 물류 대행(3PL)이냐 / 대행운영이냐**, **단일 채널이냐 멀티채널이냐**는 마케팅 결정에서 갈립니다.

**제안 (2단계):**

1. **1단계 (지금 착수):** 조직·거래 구조(1번 섹션)만 확정 → A→B + "B가 C로 보냈다"는 **출하 기록까지** 개발
2. **2단계 (마케팅 확정 후):** C 입고·대사·최종 수율 설계 — C를 **"끼워 넣는 인터페이스"** 로 두어, 같은 출하 데이터가 **어떤 창고와도 대사**되게 함

→ 경영진 마케팅 결정을 **기다리는 동안에도 1단계가 진행**되어 일정 손실이 없습니다.

## 경영진 미팅용 — 핵심 질문 9개

시간이 부족할 때 **이 9가지만** 답해 주셔도 개발 방향을 잡을 수 있습니다.

| # | 확인 사항 | Applicell 답변 |
|---|-----------|----------------|
| **1** | Applicell은 이 시스템에서 **브랜드(발주·지시)** 역할인가요? 공장·창고 역할도 직접 하나요? | |
| **2** | 이 시스템을 **모든 공장에 표준 적용**할 계획인가요, **1~2곳 파일럿**인가요? | |
| **3** | **창고(입고 확인)** 는 누가 운영하나요? (자체 창고 / 3PL / 물류사 / 공장 부속) | |
| **4** | 원자재를 공장에 보내는 주체는 **Applicell만**인가요, **여러 브랜드·법인**이 있나요? | |
| **5** | Applicell과 공장은 **Applicell이 지시·확정하는 상하 관계**인가요, **동등한 계약** 관계인가요? | |
| **6** | 수량이 안 맞을 때 **최종 확정 권한**은 누구에게 있나요? | |
| **7** | 「이번 달 ○○개」 지시의 목표는 **생산 개수**인가요, **창고 입고 개수**인가요? | |
| **8** | **수율**은 Applicell 기준으로 어떻게 정의하시나요? (보낸 원자재 대비 **창고 확인 입고**?) | |
| **9** | **1차 파일럿** 대상 공장·창고와, **성공 기준**(예: 1개 제품 end-to-end)은? | |

## 단어장 (약어·용어)

| 용어 | 뜻 |
|------|-----|
| **PO** | 발주서(Purchase Order) — A가 공장에 생산을 위탁할 때 발행하는 주문 문서 |
| **출하** | 물건을 보내는 것 — A→공장 원자재 출하, 공장→창고 완제품 출하 |
| **SKU** | 재고 관리 단위(Stock Keeping Unit) — 제품·용량·색상 등으로 구분하는 최소 코드 |
| **QC** | 품질 검사(Quality Control) — 생산품 품질 확인 (샘플 검사 등) |
| **WMS / OMS** | WMS=창고관리시스템(입출고·재고) · OMS=주문관리시스템(여러 채널 주문 통합) |
| **KPI** | 핵심 성과 지표(Key Performance Indicator) — 수율·달성도 등 경영 판단용 수치 |
| **BOM** | 자재 명세서(Bill of Materials) — 제품 1개를 만드는 원자재 구성·수량 목록 |
