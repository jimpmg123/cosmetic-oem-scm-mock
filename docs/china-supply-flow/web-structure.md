# China Supply Flow — 웹 구조

**작성일:** 2026-06-21
**최종 합의:** 2026-06-22
**목적:** 기존 A/B/C 위탁생산 목업을 보존하면서, Applicell의 실제 중국 공급 구조에 맞는 신규 웹 구조를 정의한다.

## Scope 경계 + Phasing (확정 2026-06-21 · Claude+Codex 합의)

> 본 섹션이 범위의 **단일 기준**이다. 아래 §2(1차 범위)·§8(이후 단계)은 이 결정으로 확정·대체된다.

**원칙:** 이 앱 = **통합 원장·관제 ERP**. 판매 플랫폼이 아니다.

- 판매를 *발생*시키는 것 = **OUT** — 소비자 스토어 UI, 장바구니/결제 UX, 라이브커머스·마케팅·프로모션, 리뷰/커뮤니티
- 판매 *결과* 데이터 = **IN (read-only ingest)** — 주문 원장 조회, 배송상태 조회, 반품/취소 ingest, 정산 확정 여부 조회, 정품인증
- **별도 물류 플랫폼 ❌** — 물류·채널 추적은 이 앱의 모듈로 (단일 serial/LOT 원장, 모듈 = 뷰/권한 분리)
- 거래처(지사/총판/대리상)는 Kolmar처럼 **내부 사용자로 넣지 않음** — 필요 시 "입고 확인 전용 제한 포털"만, 실적·보상·정산 직접 X

### Phasing

| 단계 | 내용 |
|------|------|
| **0차** | 외부 데이터 연동 가능성 검증 — 판매 플랫폼이 serial·배송·수령·정품인증·반품을 줄 수 있는가 (go/no-go) |
| **1차** | 제조·공급 + AP China WMS — Korea→Kolmar→AP China 입고, 제조요청·생산결과·LOT/QC·완제품 출고·입고 검수·판매 가능 전환. ★ serial/LOT/QR 저장 시작 |
| **2차** | 공식 채널 DMS — AP China→지사/총판/대리상 출고·거래처 입고 확인·채널별 재고 |
| **3차** | Traceability — serial 이동·중복 스캔·지역 이탈·외부몰 의심·정품인증 이상탐지 |
| **4차** | 연동 심화 — 주문·결제·반품·정산 대사, 검증 판매율(sell-through) |

**1차부터 원장에 박을 필드:** LOT · batch · serial/QR · outbound shipment · inbound confirmation · owner/channel · product status · hold/release

**미결(결정 필요):**
- 거래처 입고 확인 입력 방식(제한 포털 vs AP China 대행 vs 판매데이터 자동) — 禁止传销条例 민감, "입고 확인"까지만 허용.
- 정품인증 스캔 커버리지 = 하류 감지력. 인센티브 + "미스캔도 약한 이탈 신호"로 처리.

## 1. 전체 공급 구조

```text
APPLICELL Korea
브랜드 / IP / 제품기획 / 제조통제
        ↓ 제조 요청 / 발주

Kolmar China
ODM 생산 / 완제품 출고
        ↓ 입고

APPLICELL China
중국 운영법인 / 플랫폼 / 재고 / 주문 / 결제 / 정산
        ↓ 공식 채널 공급

지사 / 총판 / 대리상
        ↓ 공식 판매

소비자
```

### 역할 정의

| 구간 | 역할 | 시스템 관점 |
|------|------|-------------|
| **APPLICELL Korea** | 브랜드/IP 보유, 제품기획, 제조 요청, 제조 통제 | 제조 요청을 만들고 생산·입고 결과를 확인하는 제조 통제 주체 |
| **Kolmar China** | ODM 생산, 완제품 출고 | 외부 제조처. 로그인 사용자라기보다 발주 대상·생산 결과 기록 대상 |
| **APPLICELL China** | 중국 운영법인, 플랫폼 운영, 재고·주문·결제·정산 | Kolmar에서 완제품을 입고받고 중국 내 유통·판매를 운영하는 주체 |
| **지사 / 총판 / 대리상** | 공식 채널 공급·판매 | APPLICELL China에서 공급받아 소비자에게 판매 |
| **소비자** | 최종 구매자 | 정품 확인, 구매, 사용 후기, 재구매의 대상 |

## 2. 1차 웹 구현 범위

1차 범위는 아래 구간까지만 잡는다.

```text
APPLICELL Korea
        ↓ 제조 요청 / 발주
Kolmar China
        ↓ 완제품 출고
APPLICELL China
        ↓ 입고 검수
```

중국 유통, 플랫폼 주문, 결제, 정산, 총판·대리상 관리는 이후 단계로 분리한다.

### 1차 범위에서 살릴 개념

기존 코드의 다음 개념은 그대로 재활용 가능하다.

| 기존 개념 | 신규 구조에서의 의미 |
|-----------|----------------------|
| 제품 카탈로그 / BOM | APPLICELL Korea가 관리하는 제품·배합·제조 기준 |
| 제조 목표 수량 | Kolmar China에 요청한 생산 목표 |
| 생산 실적 | Kolmar에서 전달받은 생산 결과 |
| 출고 확인 | Kolmar 완제품 출고 |
| 입고 확인 | APPLICELL China 입고 검수 |
| 수율 | 투입 대비 회수율. 발주/투입 기준 대비 실제 입고 |
| E2E | 목표 달성률. 제조 목표 대비 실제 입고 |
| Dashboard / Table / Card UI | 제조 요청, 출고, 입고, 수율 현황 표시 |
| Mock Store 구조 | 신규 구조 실험용 mock 데이터 저장 |
| i18n 구조 | 한국어/중국어/영어 라벨 전환 |

## 3. 기존 A/B/C 모델과의 매핑

기존 화면은 `A 브랜드 → B 공장 → C 창고` 구조를 가정한다. 신규 구조에서는 이를 다음처럼 바꿔 본다.

| 기존 용어 | 신규 용어 후보 | 설명 |
|-----------|----------------|------|
| A 브랜드 | APPLICELL Korea | 브랜드/IP/제품기획/제조통제 주체 |
| B 공장 | Kolmar China | 외부 ODM 제조처 |
| C 창고 | APPLICELL China 입고처 | 중국 운영법인의 완제품 입고·검수 지점 |
| Material Bundle | 제조 요청 / 생산 배치 / 공급 배치 | 기존 "물량" 개념을 실제 거래 구조에 맞게 재정의 필요 |
| B 출고 | Kolmar 완제품 출고 | 제조처가 완제품을 APPLICELL China로 보내는 행위 |
| C 입고 | APPLICELL China 입고 검수 | 완제품 수량·상태를 확인하는 행위 |
| B 사용자 | 사용하지 않음 | Kolmar를 로그인 주체로 보기보다 외부 제조처로 기록 |

## 4. 중요한 설계 원칙

### Kolmar는 로그인 사용자가 아니다

Kolmar China는 시스템에 직접 로그인해서 매일 입력하는 `B 사용자`로 보지 않는다. 현실적인 1차 구조는 다음과 같다.

1. APPLICELL 내부 운영자가 Kolmar에 제조 요청을 등록한다.
2. Kolmar가 생산·출고 자료를 전달한다.
3. APPLICELL 내부 운영자가 해당 자료를 시스템에 등록한다.
4. APPLICELL China가 실제 입고 검수 수량을 확인한다.

즉, Kolmar는 **외부 제조처 / 발주 대상 / 생산 결과 기록 대상**이다.

### 기존 UI는 보존한다

이 변경은 단순 문구 수정이 아니라 도메인 구조 변경이다. 기존 A/B/C 운영 화면을 바로 덮어쓰지 않고, 신규 구조를 별도로 실험할 수 있어야 한다.

권장 방식:

```text
현재 코드: legacy A/B/C 운영구조로 보존
신규 브랜치: codex/china-supply-flow
좌상단 운영 옆 전환 버튼 추가
전환 상태에 따라 기존 화면 또는 신규 제조·공급 화면 표시
```

## 5. 신규 웹 메뉴 구조 초안

### APPLICELL Korea

| 메뉴 | 목적 |
|------|------|
| 제품 카탈로그 | 브랜드 라인, 제품, SKU, BOM 관리 |
| 제조 요청 | Kolmar China에 요청할 제품·수량·기한 등록 |
| 제조 진행 현황 | 생산 목표, Kolmar 생산 실적, 출고 예정 확인 |
| 수율 / E2E | 제조 목표·투입 기준 대비 APPLICELL China 입고 결과 확인 |
| 제조 이슈 | 수량 차이, 일정 지연, 품질 이슈 기록 |

### Kolmar China 관련 기록

| 메뉴 | 목적 |
|------|------|
| 제조처 관리 | Kolmar China 기본 정보, 담당 제품, 계약 정보 |
| 생산 결과 등록 | Kolmar에서 전달받은 생산 수량·불량·LOT 정보 입력 |
| 완제품 출고 등록 | Kolmar가 APPLICELL China로 보낸 출고 수량 기록 |

### APPLICELL China

| 메뉴 | 목적 |
|------|------|
| 입고 검수 | Kolmar 출고 건 대비 실제 입고 수량 확인 |
| 재고 현황 | APPLICELL China 기준 완제품 재고 |
| 공식 채널 공급 | 지사·총판·대리상으로 공급한 수량 관리 |
| 주문 / 결제 / 정산 | 이후 단계. 1차 범위에서는 제외 |

## 8. 이후 단계

이후 단계는 상단 **Scope 경계 + Phasing**을 단일 기준으로 따른다.

현재는 1차 구현 범위인 **제조·공급 + AP China 입고/WMS**를 작업 중이다. 2차 이후의 공식 채널 DMS, Traceability, 판매 결과 데이터 연동은 해당 단계 착수 시 별도 스펙으로 작성한다.
