# 경영 요약(Executive) 화면 스펙 — 경영진용

**작성일:** 2026-06-21
**대상:** Executive / 경영진 (운영 실무 아님)
**범위:** 콜마 제조 → APPLICELL Korea → APPLICELL China → 공식 유통(지사·총판·대리상) → 소비자 **전체 사업**
**관련:** [`web-structure.md`](./web-structure.md) · `docs/reports/*`

> **용어 규칙:** MLM 표현(하위·상위·모집·추천수당·조직 보상) 금지. 거래처·채널·검증 판매·정산·공급처로만 표기. (배경: 禁止传销条例)

---

## 1. 설계 원칙

경영진은 **운영 카운트를 보지 않는다.** 세 가지에만 답하면 된다.

| 질문 | 화면이 답하는 것 |
|------|------------------|
| **① 돈 벌고 있나?** | 계획 대비 매출·이익, 내 배당, 자금 막힌 곳 |
| **② 그게 진짜인가?** | **검증 판매(sell-through)** — 소비자에게 실제로 팔렸는가, 채널에 쟁여둔 것(sell-in)인가 |
| **③ 터질 건 없나?** | 채널 빼돌리기·법률(传销) 리스크·집중도 |

- **한 화면 · 신호등(🟢🟡🔴) · 예외만 드릴다운.** 정상은 접어둔다.
- "이번 달 입고 1,088개" ❌ → "**계획 대비 94% · 검증 판매율 78% · 채널 이탈 의심 2건**" ✅

## 2. 화면 레이아웃

```text
┌───────────────────────────────────────────────────────────┐
│  HERO 3   [계획 대비 매출]  [검증 판매율]  [치명 리스크 n건]   │  ← 신호등 3개
├───────────────────────────────────────────────────────────┤
│  블록1 재무 결과        │  블록2 성장 궤적                    │
├───────────────────────────────────────────────────────────┤
│  블록3 공급 건전성      │  블록4 채널 무결성/리스크 ★         │
├───────────────────────────────────────────────────────────┤
│  블록5 컴플라이언스 신호  (빨강일 때만 펼침)                  │
└───────────────────────────────────────────────────────────┘
```

라우트 제안: `/operations-2/executive` (운영 구조 2 전용, Korea Super/Admin만).

## 3. HERO 3 (최상단 신호등)

| KPI | 계산식 | 🟢 | 🟡 | 🔴 | 데이터 |
|-----|--------|----|----|----|--------|
| **계획 대비 매출** | 실적 매출 ÷ 계획 매출(기간) | ≥95% | 85–95% | <85% | P1* |
| **검증 판매율(sell-through)** | 검증 판매 ÷ 채널 출고(매입) | ≥80% | 60–80% | <60% | P2 |
| **치명 리스크** | 채널 이탈 의심 + 법률 신호 + 정산 보류 임계초과 건수 | 0 | 1–2 | ≥3 | P2 |

\* P1 = 1차(현재 mock으로 산출 가능), P2 = 2차(유통/판매 데이터 모델 필요).

> **검증 판매율이 이 사업의 1번 지표다.** 매출이 sell-in뿐이면 가짜 매출(반품·적체로 터짐)이자 法 리스크.

## 4. 블록별 KPI

### 블록 1 — 재무 결과

| KPI | 계산식 | 신호등 | 데이터 |
|-----|--------|--------|--------|
| 매출 (MTD/YTD, vs 계획) | 실적 ÷ 계획 | ≥95 / 85–95 / <85 | P1 |
| 영업이익률 | 영업이익 ÷ 매출 | 계획률 이상 / −2%p / −5%p | P1 |
| **배당 가능액** | 영업이익 × 50% (PDF 모델) | 계획 대비 | P1 |
| **운전자금 여유/부족** | 기말 제조운전자금 − 필요 제조운전자금 (정산회전 60일 반영) | ≥0 / 임박 / 부족 | P1 |

### 블록 2 — 성장 궤적

| KPI | 계산식 | 신호등 | 데이터 |
|-----|--------|--------|--------|
| 월 판매 세트 (vs 계획곡선 10,000→65,536) | 실적 ÷ 계획 | ≥95 / 85–95 / <85 | P2 |
| 활성 거래처·지역 확장 | 활성 거래처 수 추세 | 증가 / 정체 / 감소 | P2 |
| 재구매율 | 재구매 소비자 ÷ 전체 | 기준 이상/이하 | P2 |

### 블록 3 — 공급 건전성 (콜마→AP China, **대부분 1차 산출 가능**)

| KPI | 계산식 | 신호등 | 데이터 |
|-----|--------|--------|--------|
| **E2E** | AP China 입고 ÷ 제조 목표 | ≥97 / 92–97 / <92 | P1 (`calcBundleE2eFinal`) |
| **수율** | AP China 입고 ÷ grant | ≥95 / 90–95 / <90 | P1 (`calcBundleYieldFinal`) |
| **입고 보류량** | Σ max(0, 콜마 출고 − AP China 입고) | 0 / 소액 / 임계초과 | P1 (`inboundHoldQty`) |
| 재고·유통기한 임박 | useByDate 임박 재고 비중 | 낮음/중간/높음 | P1 (`useByDate`) |

### 블록 4 — 채널 무결성 / 리스크 ★ (대부분 2차)

| KPI | 계산식 | 신호등 | 데이터 |
|-----|--------|--------|--------|
| 검증 판매율(상세) | 검증 판매 ÷ 채널 출고 | ≥80 / 60–80 / <60 | P2 |
| **단계별 재고 적체(밀어내기 신호)** | 단계 매입 − 단계 검증 판매 | 낮음/증가/급증 | P2 |
| **채널 이탈·빼돌리기 의심** | 정품인증 지역 이탈 + 미활성 시리얼 + 비정상 대량 | 0 / 소수 / 다수 | P2 |
| 정산 보류 금액·반품/클로백 | 보류 정산 합·반품률 | 낮음/중간/높음 | P2 |
| 매출 집중도 | 상위 N 거래처 매출 비중 | <40 / 40–60 / >60% | P2 |

### 블록 5 — 컴플라이언스 신호 (🔴일 때만 펼침)

| KPI | 의미 | 데이터 |
|-----|------|--------|
| **sell-through 매출 비율** | 매출이 검증 판매 기반임을 보여줌 (传销 방어 핵심) | P2 |
| 미해결 분쟁/이슈 | 건수·최장 경과일 | P1/P2 |
| 집중 리스크 | 단일 제조처(콜마)·단일 법인(AP China) 정성 플래그 | 정성 |

## 5. 데이터 가용성 (구현 단계)

| 단계 | 지금 만들 수 있는 것 |
|------|----------------------|
| **1차 (현재 mock)** | 블록3 전체, 블록1(매출/이익은 단가 가정 필요), HERO의 "계획 대비 매출" |
| **2차 (유통·판매 모델 추가 후)** | 검증 판매율, 채널 적체, 채널 이탈, 집중도, 정산, 성장 궤적 |

> 1차 화면은 **공급 건전성 + 재무 결과**를 신호등으로 먼저 보여주고, 검증 판매·채널 리스크 카드는 **"2차 예정" placeholder**로 자리만 잡아두는 것을 권장.
